# TechRadar Upgrade Review

Reviewed: 2026-09-17. Repository baseline: `aa5ed97`.

## Recommendation

Make digest publication reliable, evaluate a newer model against the existing Haiku baseline, then upgrade the build stack in a separate change. Use Claude Sonnet 5 as the first quality-upgrade candidate. Keep the existing inexpensive model available until measured results justify switching. See the [implementation plan](2026-09-17-plan.md).

Scope: static review of the digest pipeline, tests, workflow, dependency manifest/lockfile, build configuration, and dashboard insight implementation. This is an upgrade assessment, not a complete security audit. No application code, dependencies, secrets, or generated feeds were changed. Bun is not on PATH and `node_modules/` is absent; tests, builds, and paid model evaluations were not run.

## Current Architecture

- `scripts/generate-feed/summarize.ts` calls Anthropic Messages with hardcoded `claude-haiku-4-5-20251001`, a 1,024-token output cap, and the first 6,000 characters of feed content.
- `scripts/generate-feed/index.ts` selects ten recent posts, summarizes sequentially, and writes digest, history, and trends into `public/data/`.
- `.github/workflows/generate-feed.yml` runs daily, scans artifacts for secrets, then commits them.
- `src/components/dashboard/AIInsight.tsx` generates headlines using local counts, thresholds, and templates. Upgrading the digest model will not turn this component into an LLM feature.
- The extension is an independent client. Maintain its existing EN/RU digest contract during migration.

## Prioritized Findings

### P1 — A failed generation can publish an empty digest

In `scripts/generate-feed/index.ts`, every summarization error is caught and skipped; the digest is then overwritten even when `items` is empty. `sources.ts` similarly returns an empty collection when all feeds fail. The workflow can therefore publish empty data with a fresh timestamp and successful exit status.

Add source-health and minimum-output gates before replacing artifacts. Retain the last good generation on failure, fail the job visibly, and test all-failed and partially-failed runs. Validate all three candidate artifacts before publication.

### P1 — Model output checks do not enforce the product contract

`summarize.ts` requests JSON in prose and extracts a brace-delimited substring. Its schema requires three nonempty takeaways but does not enforce the advertised 160-character limit or headline prefixes. The exported artifact schema accepts arbitrary category strings and unvalidated URL/date strings. Completion status and usage are discarded.

Use provider-supported structured output plus local validation. Handle truncation, refusal, empty output, and unsupported model/configuration explicitly. Keep application-owned source URLs and IDs outside model control. Validate semantic grounding separately; valid JSON does not prove factual accuracy.

### P2 — Generation cost and failures are hard to measure

The pipeline reprocesses the newest posts on each run without a persistent summary cache, model provenance, token accounting, or an application-level budget. The SDK may retry internally, but the application does not explicitly configure or record that policy. Feed fetches have no explicit deadline.

Record model, prompt/schema version, usage, duration, and failure category. Cache by normalized source identity, content hash, model, and prompt/schema versions. Bound SDK retries, fetch timeouts, and total job duration; avoid multiplying retries across layers.

### P2 — A malformed date can discard an entire source

`parseFeed()` calls `toISOString()` directly for every item. One invalid date throws out of the source parser; `fetchAllPosts()` then drops that source's complete result. Validate and skip individual malformed entries, report source/item health, and deduplicate canonical URLs before selecting the top ten.

### P2 — Build and quality checks need a reproducible baseline

The workflow uses `bun-version: latest`. The manifest aliases Vite to `npm:rolldown-vite@latest`, although the lockfile resolves a specific preview-era build. Frozen installs are reproducible, but dependency refreshes can jump unexpectedly. ESLint and `typescript-eslint` are imported/used without being direct root dependencies. The only checked-in workflow generates data; it does not enforce PR tests, lint, or builds.

Pin a tested Bun release, declare directly used tooling, and add PR verification. Separate custom live parser diagnostics from Vitest discovery: `src/server/functions/__tests__/tech-feed.test.ts` is a custom diagnostic module rather than a normal Vitest suite. This is a discovery risk identified from source, not a reproduced test failure.

Model IDs and prices: [Anthropic model overview](https://platform.claude.com/docs/en/models/overview) and [OpenAI model catalog](https://developers.openai.com/api/docs/models). Candidate roles are recommendations for this workload, not measured rankings. Haiku 4.5 remains in Anthropic's current lineup; a newer flagship does not make it obsolete.

For budgeting, calculate `input_tokens × input_rate / 1e6 + output_tokens × output_rate / 1e6` using actual billed usage. Include retries and any billable reasoning/cache usage. Do not infer tokens from the 6,000-character input limit. No cost or quality benchmark has been performed.

Anthropic supports JSON schema output through `output_config.format`; retain local Zod checks and account for the supported schema subset. See [structured outputs](https://platform.claude.com/docs/en/build-with-claude/structured-outputs). An OpenAI adapter would require its own request/response mapping rather than a model-string replacement; see [current model migration guidance](https://developers.openai.com/api/docs/guides/latest-model).
